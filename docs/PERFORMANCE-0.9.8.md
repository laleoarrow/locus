# Locus 0.9.8：保留能力，减少重复工作

这轮优化针对阅读页、图片标注和资料库的实际重复工作。没有减少可保存/可显示的标注，没有延长 Auto 避让间隔，没有关闭动态恢复、草稿保护、筛选搜索或同步能力。

## 实测结果

基线为 0.9.7 各模块修改前的计数，以及未修改的 0.9.7 浏览器构建。数据均是合成数据。下表度量调用、读取或渲染次数，**不等于整机 CPU、耗电、内存或交互耗时按同样比例下降**。

## 改动为何不会削弱能力

- 全文索引只在确实需要文本定位或新建摘录时构建，批次结束即不再由内容脚本长期保留。笔记正文、时间戳和偏好更新不再触发整页恢复；锚点改变、删除/恢复及真实页面改写继续处理。
- 并发刷新合并并保留一次后续读取。先前读取失败时仍处理已排队的更新；未排队时不自动重试，同步传输异常也不阻断下一次更新。
- 图片资源分组、祖先样式和几何缓存仅在一次同步批处理中存在，不跨帧缓存页面状态。全部几何读取完成后再写边框；改色保留原节点和定位信息。
- Library 草稿仍在 App 生命周期中保留，改为按标注 ID 通知订阅者；切筛选、切分组、折叠、隐藏期间失败重试及版本冲突保护仍在。
- Library 仍加载全部标注和锚点以支持完整搜索与批量操作；只把没有标注的访问页元数据排除在当前读取及实时依赖之外，不删除访问历史或降低 DOI 关联能力。
- Auto 的测量、障碍检查频率和避让算法保持原样，只跳过不变的 DOM 写入。

## 验证与边界

类型检查、458 项单元测试和完整一次运行的 **93 项浏览器用例全部通过**。E98/E99 确认新构建保存笔记及改色保留图片边框节点，16 图批次的布局、隐藏、裁切、滚动和重载仍正确。发行包核验见下节。

浏览器只使用 headless 临时 profile、本地页面和模拟 LLM/WebDAV；没有操作用户工作窗口、真实笔记、凭据、网盘或安装目录。没有新增产品遥测。浏览器功能测试使用同一 E2E 构建模式；本轮没有将开发构建耗时与生产构建耗时混比，也不提供未经实测的“提速百分比”。

仍存在的范围边界：Library 搜索仍需扫描完整标注集合，特大数据集没有改成分页或虚拟列表；真实网站的脚本/布局成本各不相同。未来若要量化整页 CPU、P95 输入延迟和内存峰值，应另做同机同负载的生产构建性能采样。本轮先消除已证明多余的工作，并把计数测试作为回归门槛。
