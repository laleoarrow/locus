# 0.9.10 工具条首次显示验证

用户希望工具条直接出现在目标位置，而不是先显示在默认位置，再跳到避让后的位置。

## 原因与改动

Locus 在捕获阶段接收 mouseup，排入首次显示任务；网页或其他扩展可能稍后才创建浮栏。首次测量尚未看到对方，工具条先显示在下方，约 200 ms 的下一次动态检查才将它移开。原入场动画还包含 4 px 位移和缩放。

Auto 首次显示改为隐藏等待约 300 ms，再读取当前目标与障碍。工具条的尺寸测量和坐标写入在不可见状态下完成，然后只淡入。显式 Above / Below 不增加这段等待。

数字选色在等待期间仍立即生效。重选、取消、选区折叠、禁用和保存会取消待显示任务；等待中滚动或修改偏好时，显示使用当时的几何与设置。

显示后的 200 ms 动态避让保持不变。900 ms 才出现、或之后移动的浮栏仍可能需要重新定位；不能通过短暂等待预测任意未来布局。

## 首帧证据

E103 使用同一页面的立即出现浮栏与延迟 250 ms 浮栏，连续采样 mouseup 后 700 ms 的 requestAnimationFrame。可见标准为非隐藏、正面积、opacity 大于 0.01；比较每一可见帧的实际 DOMRect 与最后一帧，检测与对方重叠。

0.9.9 基线两种场景均先显示在默认位置，再移动约 87 px；采样中分别出现 23 与 19 个重叠帧。帧数受采样频率影响，不应当作固定帧率或耗时指标。

修复后的两种场景中，所有可见帧与最终位置的最大距离均为 **0 px**，重叠帧数均为 **0**；首次可见约 330–342 ms。前后摘要见 [0.9.9 基线](toolbar-0.9.10/baseline-summary.json) 与 [修复后记录](toolbar-0.9.10/after-summary.json)。测试输出保留逐帧原始矩形；采样代码在 `e2e/toolbar-reveal.spec.ts`。

## 交互与性能约束

- E104 验证取消、选区折叠、快速重选以及等待中滚动，不得重新显示旧选区。
- E105 验证等待中按数字仍保存正确标注，且保存后不会再次弹出。
- E106 验证等待中切换到显式 Above 后立即按新偏好显示，旧任务不再改变位置。
- 保留已有慢出现、动画浮栏、图片选择、快捷键、缩放和容器选区回归。

不新增常驻轮询，不降低后续避让频率。工具条的淡入不改变几何位置；静止更新仍跳过不变的 DOM 写入。约 300 ms 的首次显示等待是为了稳定位置而引入的交互延迟，不应描述为首次显示更快。

验证只使用临时无头浏览器、本地数据及模拟服务；不改用户正在使用的扩展目录或工作窗口。
